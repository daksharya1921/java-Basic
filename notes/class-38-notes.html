🧠 Key Concepts

What is Functional Programming? (High Level)

Functional programming focuses on what needs to be done, rather than how it's implemented step by step. Before Java 8, Java did not support this style — other languages already did, and market demand pushed Java to add support for it.

Functional Interface — Definition

A functional interface is an interface with exactly one abstract method (also called a Single Abstract Method, or SAM). This single-method constraint is what makes lambda expressions possible — Java can unambiguously know which method a lambda expression is implementing.

Marker vs Functional Interface — Quick Contrast
  • Marker interface — zero methods (empty)
  • Functional interface — exactly one abstract method
Why Only One Abstract Method?

If a functional interface had two or more abstract methods, Java wouldn't know which method a lambda expression is meant to implement when you don't specify a method name — this would create ambiguity. Restricting to a single abstract method removes that ambiguity entirely.

Lambda Expression — What It Achieves

A lambda expression lets you implement a functional interface's single method without writing a full class, without extending/implementing anything explicitly by name, and without naming the method — you just supply the parameters and the logic directly, and Java infers everything else based on the interface's single abstract method signature.

Traditional Implementation vs Lambda — The Simplification

Traditionally: declare interface → create a separate implementing class → override the method → create an object of that class → call the method. With lambda expressions, all of that collapses into essentially one line: assign a lambda expression directly to a variable of the functional interface's type.

@FunctionalInterface Annotation

An optional annotation placed above an interface declaration. It doesn't add functionality — it acts as a compile-time safety check: if someone later accidentally adds a second abstract method to an interface marked @FunctionalInterface, the compiler throws an error, preventing accidental breakage of code relying on that interface's lambda-compatibility.

Default, Static, and Private Methods Don't Affect Functional Status

A functional interface can have any number of default, static, and private methods alongside its single abstract method — none of these count toward the "single abstract method" rule. Only the count of abstract methods matters.

Interface Inheritance and Functional Status

If one functional interface (one abstract method) extends another functional interface (also one abstract method) with a different method signature, the child interface effectively ends up with two abstract methods total — meaning the child is no longer a valid functional interface, even though each parent individually was.

Built-in Functional Interfaces (java.util.function, since Java 8)
InterfaceMethodPurpose
Predicate<T>test(T t)Takes input, returns boolean (a condition check)
Supplier<T>get()Takes no input, returns a value
Consumer<T>accept(T t)Takes input, returns nothing (just "consumes" it)
Function<T,R>apply(T t)Takes input, transforms it, returns a result
Predicate — Condition Checking

Use when you want to check a condition and get a true/false result, without writing a full if-else block manually — e.g. "is this number less than 100?"

Supplier — No Input, Just Output

Use when you don't need any input but want some generated output — classic example: generating an OTP or account number, where nothing is "supplied" to the logic, it just produces a value.

Consumer — Input, No Output

Use when you want to "consume" an input and perform an action, without expecting any return value — e.g. sending an email (you pass the email address, it sends the email, nothing is returned).

Function — Input, Transform, Output

Use when you want to take an input, apply some transformation/calculation, and return a result — e.g. applying a discount formula to an amount and getting back the discounted value.

💻 Code Snippets / Examples

Traditional way vs lambda — custom functional interface:

interface MyInterface {
    int add(int a, int b); // implicitly public abstract
}
// Traditional way
class AddImpl implements MyInterface {
    @Override
    public int add(int a, int b) {
        return a + b;
    }
}
MyInterface obj = new AddImpl();
System.out.println(obj.add(2, 3));
// Lambda way — no separate class, no method name
MyInterface myInterface = (x, y) -> x + y;
int sum = myInterface.add(2, 3); // 5

@FunctionalInterface — prevents accidental breakage:

@FunctionalInterface
interface MyInterface {
    int add(int a, int b);
    // int subtract(int a, int b); // uncommenting this causes a COMPILE ERROR
    //  — "MyInterface is not a functional interface"
}

Custom functional interface — discount application:

@FunctionalInterface
interface Discount {
    int applyDiscount(int amount);
}
Discount discount = (amt) -> {
    int disc = amt * 5 / 100;
    return amt - disc;
};

System.out.println(discount.applyDiscount(1000)); // 950

Predicate — condition checking:

import java.util.function.Predicate;

Predicate isLessThan100 = (number) -> number < 100;

System.out.println(isLessThan100.test(50));  // true
System.out.println(isLessThan100.test(150)); // false

Supplier — no input, generates output (e.g. OTP):

import java.util.function.Supplier;
import java.util.Random;

Supplier otpGenerator = () -> new Random().nextInt(9000) + 1000;

System.out.println("Your OTP is " + otpGenerator.get());

Consumer — input, no return (e.g. sending email):

import java.util.function.Consumer;

Consumer emailSender = (email) -> System.out.println("Email sent to " + email);

emailSender.accept("user@example.com"); // "Email sent to user@example.com"

Function — input, transform, output (e.g. discount calculation):

import java.util.function.Function;

Function discountFunction = (amt) -> amt - (amt * 5 / 100);

System.out.println(discountFunction.apply(100)); // 95

📌 Important Points / Common Mistakes

  • A functional interface must have exactly one abstract method — additional default/static/private methods don't count against this.
  • Lambda expressions implement a functional interface's single method implicitly — no method name is written.
  • @FunctionalInterface is optional but helps catch accidental additional abstract methods at compile time.
  • Know the four core built-in functional interfaces and their exact method names — this is a very common interview question: Predicate (test), Supplier (get), Consumer (accept), Function (apply).
  • Predicate always returns boolean; Supplier takes no input; Consumer returns nothing; Function transforms input to output.
