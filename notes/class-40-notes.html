Class 40 — Shallow Cloning vs Deep Cloning

🎯 Topics Covered

  • Recap: cloning basics, Cloneable, overriding clone()
  • Why cloning is needed (avoiding expensive re-creation of similar objects)
  • Shallow cloning — Java's default clone behavior
  • Deep cloning — cloning nested/dependent objects explicitly
  • How to identify shallow vs deep clone through shared vs separate references
  • Implementing deep cloning manually

🧠 Key Concepts

Recap: Why Clone Instead of Creating a New Object?

Creating a brand-new object from scratch (supplying every field again) can be more "expensive" (in effort/logic) than copying an existing, already-populated object and just modifying what's different. Analogy: reusing a photocopy of your Aadhar card is easier than requesting a fresh printed copy each time; similarly, apps like PhonePe let you "send again" to reuse a previous transaction's details instead of re-entering everything.

Recap: Cloning Requires Permission

A class must implement the Cloneable marker interface and override the inherited clone() method (making it public) — otherwise calling .clone() throws CloneNotSupportedException.

Shallow Cloning — Java's Default Behavior

When a class has a field that is itself an object of another class (a "nested" or dependent object — e.g. an Employee that has an Address field), Java's default clone() behavior only copies the top-level object. The nested object's reference is copied, not the nested object itself — meaning both the original and the cloned object end up pointing to the exact same nested object in memory.

The Consequence of Shallow Cloning

Because the nested object is shared, modifying it through either the original or the cloned object affects both — since there's really only one nested object being referenced by two different parent objects. This can be a surprising and dangerous bug if you expect the clone to be fully independent.

Deep Cloning — Explicitly Cloning Nested Objects

To make the clone fully independent of the original, you must manually clone the nested object(s) too, inside your overridden clone() method — assigning the newly cloned nested object to the cloned parent object's corresponding field. This requires the nested class to also implement Cloneable and override its own clone().

How to Tell Shallow vs Deep Apart

After cloning, modify the nested object's field through the cloned object. If the change also appears in the original object → it was shallow (shared reference). If the original remains unchanged → it was deep (fully separate copy).

💻 Code Snippets / Examples

Setup — Employee has a nested Address:

class Address implements Cloneable {
    String line1;
    String city;

    public Address(String line1, String city) {
        this.line1 = line1;
        this.city = city;
    }

    @Override
    public Object clone() throws CloneNotSupportedException {
        return super.clone();
    }
}

Shallow clone — Java's default (only override employee's clone, don't touch address):

class Employee implements Cloneable {
    String name;
    Address address;

    public Employee(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    @Override
    public Object clone() throws CloneNotSupportedException {
        return super.clone(); // SHALLOW — address reference is just copied, not cloned
    }
}
Address address1 = new Address("BTM", "Bangalore");
Employee e1 = new Employee("Nitya", address1);
Employee e2 = (Employee) e1.clone(); // shallow clone

e2.address.line1 = "Test Address"; // modifying through e2...
System.out.println(e1.address.line1); // ALSO prints "Test Address" — shared object!

Deep clone — manually clone the nested object too:

class Employee implements Cloneable {
    String name;
    Address address;

    public Employee(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    @Override
    public Object clone() throws CloneNotSupportedException {
        Employee cloned = (Employee) super.clone();
        cloned.address = (Address) this.address.clone(); // DEEP — clone the nested object too
        return cloned;
    }
}
Address address1 = new Address("BTM", "Bangalore");
Employee e1 = new Employee("Nitya", address1);
Employee e2 = (Employee) e1.clone(); // deep clone

e2.address.line1 = "Test Address"; // modifying through e2...
System.out.println(e1.address.line1); // still prints "BTM" — SEPARATE object now!
System.out.println(e2.address.line1); // "Test Address"

📌 Important Points / Common Mistakes

  • Java's default clone() behavior is shallow — nested object references are shared, not duplicated.
  • To achieve a deep clone, you must explicitly clone each nested/dependent object inside your overridden clone() method.
  • Nested classes must also implement Cloneable and override clone() to support being deep-cloned.
  • Shallow cloning can cause subtle bugs where modifying a "cloned" object unexpectedly affects the original, via shared nested references.
  • Always test cloning behavior by modifying a nested field and checking whether the original is affected.
